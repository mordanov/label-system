# Промпт для Claude Code: генерация недостающей иконки через OpenAI gpt-image

Контекст: в системе учёта продуктов при создании записи пользователь выбирает иконку блюда из готовой галереи (`assets/icons/*.png`, статично зашита в образ backend через `COPY` в Dockerfile). Нужна фича: если подходящей иконки в галерее нет, пользователь может сгенерировать новую по названию блюда через OpenAI Image API (модель `gpt-image-1`), и она добавится в галерею для дальнейшего переиспользования.

## Стиль иконки (обязательно соблюсти)

Ориентируйся на приложенный образец листа иконок — стиль строгий line-art:
- Только чёрный контур на белом/прозрачном фоне, без заливки цветом и без полутонов/градиентов.
- Единая толщина линии по всем иконкам, скруглённые углы, минимум деталей (иконка должна быть узнаваема силуэтом, не фотореалистична).
- Композиция — один центральный объект (продукт/блюдо), при необходимости в простой миске/банке/тарелке, как на образце.
- Ничего лишнего: без теста, без фонового рисунка, без подписей на самой иконке.

Приложи образец листа иконок как референс прямо в промпт к `gpt-image-1` (через image input, если API поддерживает referencing/edit по образцу) и/или подробно опиши стиль текстом в промпте — так, чтобы сгенерированная иконка визуально сочеталась с уже существующей галереей.

## Логика фичи

1. **Backend-эндпоинт** `POST /icons/generate` с телом `{ "dish_name": "..." }`:
   - Формирует промпт для `gpt-image-1` на основе `dish_name` + фиксированного описания стиля (см. выше).
   - Вызывает OpenAI Images API (ключ — `OPENAI_API_KEY` из `.env`, не хардкодить).
   - Постобрабатывает результат: приводит к строгому чёрно-белому (1-бит) изображению (порог/дизеринг через Pillow), убирает фон до однородного белого/прозрачного, обрезает/масштабирует под квадратный формат, согласованный с остальными иконками галереи.
   - Сохраняет файл в отдельную поддиректорию `assets/icons/generated/` (не путать со статичной `assets/icons/` — генерируемые иконки не должны требовать пересборки образа) с именем, производным от `dish_name` (транслитерация/слаг + уникальный суффикс на случай коллизий).
   - Регистрирует иконку в БД (таблица `icons` или расширение текущего способа отдачи `GET /icons`, если иконки сейчас просто читаются из файловой системы — тогда просто убедиться, что `GET /icons` включает и `assets/icons/`, и `assets/icons/generated/`).
   - Возвращает клиенту сгенерированную иконку (filename + сама картинка/URL) для предпросмотра.

2. **Персистентность.** `assets/icons/generated/` должна быть смонтирована как Docker volume (не как часть образа), чтобы сгенерированные иконки не терялись при пересборке/обновлении backend-контейнера.

3. **Кэширование/дедупликация.** Перед генерацией проверить, нет ли уже иконки с похожим/нормализованным названием блюда в `generated/` (по слагу имени) — если есть, предложить пользователю использовать существующую вместо повторной генерации (экономия вызовов API).

4. **Frontend.** В форме создания продукта, если пользователь не находит подходящую иконку в галерее, добавить кнопку/раздел «Сгенерировать иконку по названию» → поле ввода (по умолчанию — уже введённое название продукта, с возможностью подправить формулировку под генерацию) → кнопка «Сгенерировать» → показ превью результата → кнопки «Использовать» (сохраняет выбор для продукта) или «Сгенерировать заново» (с тем же или изменённым названием).

5. **Обработка ошибок.** Таймауты/ошибки OpenAI API, невалидный `OPENAI_API_KEY`, превышение квоты — отображать понятную ошибку на фронте и не ронять создание продукта: пользователь в любом случае может выбрать существующую иконку из галереи как запасной вариант.

6. **.env.** Добавить `OPENAI_API_KEY` в `.env.example` (пустым/плейсхолдером).

## Не менять

Существующую логику печати, галерею статичных иконок, эндпоинты продуктов — эта фича добавляет только способ пополнения галереи, не меняя остальной функционал.
